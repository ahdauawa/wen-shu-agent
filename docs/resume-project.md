# 简历项目描述（按当前实现）

**问枢｜面向 SaaS 帮助中心的文档客服与工单分流系统**

技术栈：Python、FastAPI、LangGraph、BGE-M3、Chroma、DeepSeek API、SQLite、Pydantic。

- 基于 LangGraph 实现知识咨询、工单查询/创建、人工交接等七类意图路由，设置最多两轮澄清，并对无检索结果、证据不足和模型异常提供交接降级。
- 引入 27 篇开源官方帮助文档，完成 MDX 引用展开、按章节切分与 152 个片段的向量索引，支持中文提问检索英文资料；为回答提供章节、原文片段和固定版本链接。
- 实现带引用 ID 的结构化生成，校验引用是否来自检索结果；使用内容指纹隔离不同文档版本，避免更新或删除文档后仍查询旧索引。
- 通过 Pydantic 校验工单工具参数，结合创建前确认、SQLite 事务、请求唯一约束及用户归属校验，实现幂等重试和用户数据隔离。
- 编写 42 条中文检索评测题，分为 12 条校准题和 30 条测试题；在测试集 24 条有答案问题上，未加阈值的文档级 Recall@5 为 23/24，加阈值后为 21/24，记录漏召回和无答案误接受案例。

只在完成代码学习并能独立解释后将对应能力写入个人简历；上面的数字是本项目小样本检索实验，不能写成生产准确率。不沿用参考材料中的 500+ FAQ、P99、线上 CSAT、真实业务收益等未经本项目验证的数据。项目时间应按实际学习与开发时间填写，Git 使用真实提交时间。

## 面试前需要跑通

1. 打开知识库目录，解释 MDX 原文、转换后的 Markdown、chunk 与向量的区别。
2. 展示一次中文问答，逐项核对引用片段与原文。解释“命中文档”和“证据足够回答”的区别。
3. 加一篇自己的 Markdown，重建索引、重启，说明为什么索引指纹发生变化。
4. 演示预览工单、确认提交、相同请求重试、跨用户访问拒绝。
5. 阅读评测失败样例，解释阈值提高会同时减少误接受和增加漏召回；不要把测试集当作调参集。
